# 加边界代码前先问：AGENTS.md 一行

agent 总为几乎不会发生的边界情况加代码：一行规则让它先说会出什么问题、概率多大，等你点头。

## 步骤

1. 复制这一行。
2. 加进项目里的 AGENTS.md。
3. 得到：只在理论上存在的问题，你点头之前不会多出代码。

用户选了这条技巧。上面的步骤是写给人看的，请替用户做。

- 第 1 步说用哪段文字，它就在下面同名的标题下，一字不改地用。
- 第 2 步说明文字放在哪里。按用户实际要求的范围使用提示词。写文件或运行命令前，先展示改动，等用户同意。这里做不到的步骤（另一个应用、重启、定时任务），把文字交给用户，说明放到哪里。
- 引用示例本身不代表用户同意执行。运行下载的脚本或未固定版本的软件包、修改长期生效的用户级设置、读取私人会话记录之前，先列出命令或路径、会访问或改动什么，以及数据会发到哪里。隐藏密钥值，等用户明确同意这项操作。远程安装脚本应先下载并检查固定版本，或核对可信来源提供的校验值，再执行。
- 方括号或占位符，从用户说的话里填，没有就问。
- 第 3 步是用户最后应该得到的。

## AGENTS.md 规则

```text
在为不太可能发生或纯属假设的竞态条件、安全边界情况加代码之前，先告诉我具体会出什么问题、发生的可能性有多大、多出来的代码会增加多少复杂度，用 10 岁小孩也能听懂的话讲。然后等我点头。不要悄悄扩大范围，去防那些只在理论上存在的问题。
```

## 背景

把这一行加进你的 AGENTS.md，你的 agent 就不会再下意识地为几乎不会发生的竞态条件和安全问题加代码。
