# 常驻的几行

有三件事等不到 Copybook 技能加载：把范围越改越大、凭猜测动手改、报告怎么排。agent 自己察觉不到正在这么做，所以只有一直在上下文里的几行才管用。下面这一段就是这几行。前五行不需要装任何东西；最后一行在装了 Copybook 时把 agent 引到四条技巧。

它放进这个项目的 agent 每次都会读的文件：AGENTS.md、CLAUDE.md，或两个都放（两种 agent 各读各的、互不包含时）。原样给用户看，用户同意再加（SKILL.md 第 4 步）。不要加第二遍；用户说过不用，这个会话里不再提。

```markdown
## Copybook
- 动手改之前，先读相关代码，用一句话说清原因或需求。不凭猜测改。
- 只改要求改的。顺带发现的其他问题列在最后，不要修。
- 同一个 bug 修了两次还没好，不要凭猜测修第三次。先只查不改，拿到证据后，回复以 `Copybook:` 开头，说清试过什么、证据说明什么、需要我决定什么。
- 长报告里，需要我做的事放最前面，编上号。
- 我第二次纠正同一个错时，提议往这个文件加一行，免得再犯。
- 装了 Copybook（技能或 MCP）时，按这里写的标题找到技巧，并说一句 `Copybook: 用 <技巧>`：
  - 计划写好了，还没动代码：「一条消息里的 5 种计划复查方法」
  - 跨好几个文件的改动做完了，提交或开 PR 之前：「影响范围、红队等 5 条让模型判断的提示词」
  - 网站要上线了：「上线前网站检查：20 项页面」
  - 工作要交接或暂停：「边做边写给下一个 agent 的 HANDOFF.md」
```
