# 动手前的市场判断

还没调研就给建议：25-40 家竞争对手逐家记下，反复出现的抱怨排好序，再看你的方向会死在哪。

## 步骤

1. 复制提示词。
2. 发给 Opus 5.5，空白处先填上你想做的东西。
3. 得到：market/ 里的两份文件，再看你选定方向最有力的理由和它会死在哪。

用户选了这条技巧。上面的步骤是写给人看的，请替用户做。

- 第 1 步说用哪段文字，它就在下面同名的标题下，一字不改地用。
- 第 2 步说明文字放在哪里。按用户实际要求的范围使用提示词。写文件或运行命令前，先展示改动，等用户同意。这里做不到的步骤（另一个应用、重启、定时任务），把文字交给用户，说明放到哪里。
- 引用示例本身不代表用户同意执行。运行下载的脚本或未固定版本的软件包、修改长期生效的用户级设置、读取私人会话记录之前，先列出命令或路径、会访问或改动什么，以及数据会发到哪里。隐藏密钥值，等用户明确同意这项操作。远程安装脚本应先下载并检查固定版本，或核对可信来源提供的校验值，再执行。
- 方括号或占位符，从用户说的话里填，没有就问。
- 第 3 步是用户最后应该得到的。

## 提示词

```text
我想做 ___。先别给建议：
1. 找出这个品类里 25–40 家竞争对手，逐家读它们的定价页、客户案例和文档。在 market/index.md 里每家写一行：卖给谁、怎么收费、主打什么。
2. 然后读 100+ 条用户评价和论坛上的抱怨。把反复出现的抱怨按出现次数排序，每条附上来源，存到 market/complaints.md。
3. 只根据这些材料回答：这个市场里的赢家知道什么、却绝不会对客户承认？整个行业把哪些假设当成理所当然，每一条在什么情况下会不再成立？
4. 等我定下方向，先像顶级 VC 那样为它讲出最有力的理由，再告诉我它会死在哪。最后列出 3 个我该拿去问真实客户的问题。
```

## 背景

Opus 5.5 能给你一份 10 年老手的市场判断，前提是你先让它把市场读一遍。
