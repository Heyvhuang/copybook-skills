# Codebase · 36 tips

Copybook's 36 tips on codebase. The order is by saves, not by fit: read the whole list before choosing, since the tip that fits is often further down. Each tip's file is `../codebase-tips/references/<name>.md`.

| Tip | What it does |
| --- | --- |
| open-source-scout-and-closer | Unfamiliar features written from scratch, offers to continue: GitHub searched first, then the whole job done and a plain recap. |
| codebase-memory-repo-index | Dozens of grep and read turns per question: the repo as one graph of functions, files and dependencies; dead code found too. |
| delete-first-project-prompt | Broken or unneeded code, pages with hierarchy problems: deleting preferred, what it's sure about fixed, the rest listed. |
| karpathys-4-coding-principles | The agent over-designs and edits what it wasn't asked to: think before coding, simplicity first, surgical edits, goal-driven work. |
| vibe-coding-cleanup-prompts | Half your quota left at reset: dead code, duplicates and unneeded dependencies cut; scheduled tasks and old worktrees sorted. |
| clickable-repo-map | Before you change a repo: click any module for its callers, dependencies, tests and source evidence; a rule keeps it current. |
| scope-guard-rules | Asked to change a config, it builds a framework: minimum sufficient change, reuse first, ask before widening, test narrowly. |
| disk-map-of-dev-leftovers | Disk almost full: a read-only scan, a treemap of what development left behind, and a cleanup script only for what you tick. |
| one-agents-md-for-both-agents | Two agents, one rules file: plan first, smallest change, subagent roles, own the bug, verify before done, Lessons per correction. |
| untangle-goal | Months of vibe coding left the code in knots: an HTML wiring diagram, the worst numbered in red, then fixes tested one by one. |
| investigate-and-plan-prompt | Before it implements on a guess: repo read, goal restated, assumptions and plan listed, then a stop for your approval. |
| pr-comments-as-agents-md-rules | A reviewer keeps flagging the same things: 50 recent PRs scanned, issues ranked by count, your picks written into AGENTS.md. |
| archify-system-diagrams | A system you have to explain: an HTML diagram you can search, trace up and downstream, compare across versions, export as PNG. |
| rea-take-apart-a-feature | A feature you like and can't see how it's built: taken down layer by layer, each finding with evidence, then a plan for your own. |
| less-defensive-code | Even a tiny change gets null checks at every layer: Codex checks data once where it comes in, then just uses it. |
| fewer-deeper-modules | A feature works, but the code repeats itself: duplicates wiped out and the core logic in one place. |
| ci-time-audit | Code takes minutes, then each PR waits on CI: the 5 slowest jobs split into queue, setup and run, and the line to change per fix. |
| agent-workspace-audit | Your agent feels dumber over time: every instruction, skill, MCP and memory marked KEEP or REMOVE, cleared on your OK. |
| agent-memory-tools-8-repos | No memory of code, notes, sessions or long tasks: 8 repos in those 4 kinds, one of each installed on your OK. |
| mac-disk-reconciliation | Disk nearly full and Finder doesn't show why: the disk reconciled for hidden usage, a cleanup plan checked against your projects. |
| whole-project-audit | Broken, inconsistent or unneeded code: how it connects explained before any change, what it's sure about fixed, the rest listed. |
| 3-slimmer-agents-md-plans | AGENTS.md past 200 lines gets followed less: 3 slimmer versions, each more aggressive, nothing lost, shown before changes. |
| no-compatibility-code-yet | No users yet, but the agent adds compatibility code and migrations: skip both, then docs, tests, smallest change and cleanup. |
| deny-ask-and-allow-permissions | Claude deleted a config that 'looked unused': risky commands blocked, pushes ask first, routine ones run, deny always wins. |
| ask-before-edge-case-code | The agent codes for races that never happen: one line makes it state the risk and the odds, then wait for your OK. |
| instructions-from-your-sessions | Background you re-explain every new session: pulled from your last 20 sessions and written up as project instructions. |
| mod-request-for-claude-code | Something in Claude Code's interface you want changed: a prompt that finds an existing Mod or proposes the smallest one. |
| codex-and-claude-sorted | A cleanup that could delete your chats: items sorted Keep, History, Work, Clearable or Unknown, each command approved by you. |
| mod-ideas-from-20-sessions | Requests you repeat, commands you stop or undo, how you check changes: ranked by how much each would help, your words quoted. |
| teach-strategic-programming | Spend tokens learning what AI can't replace: 3 questions about your codebase, then MISSION.md, a curriculum and lessons on it. |
| bug-fix-loop-rules | Agents that both fix and review can't stop going back and forth: stop after two failed fixes, review only this round's changes. |
| ub-mode-clean-code-agent-rules | Your agent's code hides bugs and its tests fool you: a skill it follows on every change, with crapper, dryer and mutator checks. |
| repo-map-words-vs-names | What you call a module isn't what the code calls it: every mismatch marked in red, those likeliest to cause a wrong edit first. |
| outdated-claude-md-review | Agents follow an outdated CLAUDE.md over your code: its old instructions identified, and a rule that puts code first. |
| repeat-mistakes-as-lint-rules | The agent keeps making one mistake: the right way in a helper, the old way banned by lint, an error that names the helper to use. |
| situation-routing-for-skills | Your agent often forgets to use what you install, so you call each by name: the best fit per task, with one line on which and why. |
